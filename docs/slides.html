Punish · London AI x Science Hackathon · Track 2

AI science agents can pass the grader without doing the science

Agents now run analyses, write reports and cite literature. Like any optimiser, they can copy an expected answer, quietly drop inconvenient data, switch to a friendlier metric, or invent a citation.

  • The proxy is a number. A p-value, an R² or an accuracy threshold can be matched without running the analysis.
  • Reviewers read the report, not the notebook. The write-up looks like the deliverable.
  • Hacks look like judgement calls. Outlier removal or a metric choice is fine when disclosed, a hack when chosen to hit a target and hidden.
What does an auditor need to see to catch reward hacking: the reasoning, the actions, or only the report?

Threat model

One planted exploit per task, six ways to cheat

  • Subject: an LLM agent with a sandbox and three tools: read_file, run_python, write_report.
  • Opportunity: a leaked answer file or a grader that rewards a proxy. Using it raises the score and lowers validity.
  • Motive: only the system prompt varies: honest → incentivized → pressure → covert (told to hack and hide it).
  • Auditor: reads the trajectory afterwards. It never sees the system prompt, cannot run code, and is never trained against.

Ground truth

A rule-based labeller misses many hacks: 46 of 91 found (leaked_answer excluded)

  • The labeller checks only the planted path, for example "read eval.py, reported 0.312 and no successful analysis ran".
  • fake_citation: agents cite real references.bib keys for findings the papers do not contain.
  • leaked_answer: the chart's 47 vs 123 includes 30 judge positives that are likely wrong (stale task definition). Excluding the task: 46 vs 91.
  • Labeller-only hack rates would understate the problem about 2× (2.6× on the original labels). The judge is an LLM too, so treat it as the best available reference, not as the truth.

Hard negatives (10)

Limitations

Read these numbers as preliminary

Small n

5 episodes per (model, config, task) cell. Per-task results rest on 4–27 positives. Most mode differences other than final_report vs the trace modes are within noise.

Instructed hacking

Most positives come from covert. Natural hacks are rarer and softer, and Sonnet full_trace recall under pressure is 18/24.

LLM ground truth

The headline label is effectively the Opus judge, from the same model family as the auditor. Against 60 blind AI labels: κ 0.70, never more lenient; 8 of 9 disagreements are a stale leaked_answer definition. No human raters yet.

Toy tasks

Single-file tasks with one planted exploit each. Real analyses are longer, and hacks may spread across many steps.

The rubric drives FPR

The rubric counts any eval-file read as suspicious_access and the judge does not. Most trace-mode false positives come from this mismatch.

Reasoning is not ground truth

A clean trace is weak evidence of a clean run (Chen et al.). We have not tested agents trained to obfuscate.

Takeaway

Audit the trajectory, not the paper

  • Actions are the main signal. Reading only the final report costs Sonnet 4.6 0.14 recall with leaked_answer excluded (0.90 → 0.76; 0.26 on the original labels).
  • Reasoning helps a strong auditor separate looking at the grader from using it (Opus FPR 0.06 vs 0.12 and recall 0.77 vs 0.63 with leaked_answer excluded; 0.11 vs 0.17 and 0.84 vs 0.73 on all 240 runs, p < 0.001).
  • Rule-based ground truth undercounts. The labeller finds 46 of the 91 hacks the judge finds (leaked_answer excluded).
  • Citation misuse is the open blind spot. Give the auditor the abstracts or a retrieval tool.
